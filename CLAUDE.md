## What this is

Pipe Assessor is a **no-build, single-page static web app**: **`index.html`** is the Findings Tracker dashboard (the Render root) — a Supabase-backed register of abnormal inspection findings tracked from Open until repaired/closed, with the **full ASME B31.3 assessment workbench built in**. The workbench evaluates pipe wall-thickness integrity per **ASME B31.3** (required thickness / MAWP) and **ASME PCC-2** (repair category advice), with API 574 structural minimums as a secondary check — a field engineer enters the measured wall loss and gets a live status (OK / MONITOR / REPAIR), cross-section diagram, results table, repair advisor, substituted equations, remaining-life estimate, and a generated PDF engineering report. The whole app requires sign-in and a network connection (Supabase + CDNs); offline it degrades to a login screen with a "check your connection" notice.

**History note:** the standalone **`calculator.html` was retired and deleted** when its entire presentation layer was merged into the dashboard (form workbench + `#/calc` quick-calc route + unified PDF). Its git history holds the original implementation — and before the Phase-4 swap the calculator was `index.html` and the tracker `findings.html`, so calculator history lives under both names. The deliberate trade-off of the retirement: there is **no offline/no-login calculator any more**; `#/calc` needs the signed-in dashboard.

Three shared local files (still no build step):
- **`asset/theme.css`** — the design system's single source of truth: brand tokens (single light palette — the app has no dark mode), the Basecoat token-alias block, base styles, `.wrap` (max-width **1500px**), the app header suite (`body > header` is **position: sticky, top: 0, z-index: 100** — anything else sticky must offset below it, see `--app-header-h`), the number-spinner removal, `.mono`, **and the assessment-workbench component CSS** (status banner, compliance box, ERF gauge, `.res-grid`, advisor list, `.eq-*` equation blocks, `.assess-svg` hover-highlight rules, `.drag-handle`) — plus `.panel`/`.panel-h`/`.panel-b`/`.panel-collapse`, the app's one card-container system, shared by the dashboard's plain panels and the workbench's collapsible `<details>` sections alike (no separate hand-rolled clone). **Never re-inline these blocks into the page**; the page `<style>` holds only page-specific components. Load order: Basecoat CDN CSS first, `theme.css` after it.
- **`asset/shared.js`** — shared JS globals: the Supabase URL/key constants (`PA_SUPABASE_URL`/`PA_SUPABASE_KEY`); `paFmtDate` (dd/Mmm/yyyy, `—` for invalid); `paFmtBaht`/`paFmtBahtShort` (Thai Baht — full `฿1,250,000` / abbreviated `฿2.4M`); `downscaleImage`; the embedded base64 **`OR_LOGO_DATAURL`** (header + PDF logo, embeds even offline); `registerGoogleSansFonts` (jsPDF font embedding); **and the ASME B31.3 engine** — `PA_PIPE_DATABASE`, `PA_MATERIALS`, `paGetApi574Min`, `paDefaultScheduleForNps`, `paFmt`, and the pure **`computeB313(params) → result`** (the single source of the wall-thickness math, consumed by every assessment surface). Loaded with a **non-defer** `<script>` in `<head>` on purpose — the inline script references these globals at parse time; keep the file dependency-free. **`computeB313` is DOM-free and side-effect-free** — it returns an `errors` map (keys: `overrideTnom`/`overrideOd`/`P`/`S`/`depth`/`tmeas`/`ca`) the caller reflects onto its own UI, plus the full result object. **CA (corrosion allowance) is a forward-looking reserve, not the measured loss** — `CA ≥ t_meas` is deliberately **not** an error (a thin pipe whose remaining wall is already at/below its allowance is a valid, meaningful case: the no-CA headline ERF/MAWP still computes at the measured thickness, and the status margin — which includes CA — correctly reads REPAIR). Only `ca < 0` errors. In that case `mawp_with` is returned as **null** (and `caExceedsWall: true`), which every surface renders as "n/a — wall below CA" rather than a misleading 0/pegged-ERF. Any change to the engine must pass the numeric-identity regression (`compute-parity.js`: current build vs the last git-committed math, across a matrix of sizes/schedules/materials/modes/overrides — must be 0 mismatches **except** intended changes like this CA one, where the only diffs are the previously-blocked `CA ≥ t_meas` cases).
- **`asset/assess-ui.js`** — the **assessment workbench view layer** (loaded non-defer, after `shared.js`, before the inline script). Extracted 1:1 from the old calculator page and verified value-identical against it at extraction time. Exposes:
  - **`paCreateAssessView(root, opts) → view`** — injects the workbench markup into `root` and returns `{ render(res, ctx), getSvg(), getLastRes() }`. `opts.sections` picks blocks in order from `status | scope | svg | results | advisor | equations`; `opts.collapsed` lists sections rendered as closed `<details>`; `opts.onDepthDrag(depth_mm)` enables the SVG drag handle (omit it for read-only views — the handle stays hidden). `render(res, ctx)` takes a `computeB313` result (or null) and `ctx = { neutral, nps }` — `neutral: true` shows the grey "enter data to begin" banner instead of a red ERROR (the cold-form rule). **The markup carries no element ids** — every lookup is `data-k` scoped to the instance root, so multiple instances coexist in one document (form, detail page, quick calc).
  - **`paAdvisorItems(res)`** — pure PCC-2 advisor content, shared by the DOM list and the PDF.
  - **`PA_SCOPE_HTML` / `PA_SCOPE_TEXT`** — single source of the Scope & Limitations text (on-screen notice + PDF section).
  - **`paSvgToPng(svgEl, scale)` / `paCrossSectionPng(res, scale)`** — SVG→PNG rasterization for the PDF figure. The injected fixed light-palette `<style>` (CSS variables don't resolve in a standalone serialized SVG) must stay in sync with theme.css's light-mode `--svg-`*/`--limit-`* values; text font-family is rewritten to Arial (webfonts don't exist in the isolated SVG context). `paCrossSectionPng` mounts an offscreen svg-only view, renders, rasterizes, and resolves **null on failure** so PDF builders degrade instead of throwing. **Never put `*/` inside a JS block comment in this file** (e.g. a `--svg-*/--limit-*` glob) — it terminates the comment and breaks the whole script.

No package.json or build tooling. Development is editing `index.html` + the three asset files directly. CDN dependencies (pinned versions, static `defer` tags): **Basecoat CSS 1.0.1** (shadcn/ui-style component classes; brand colors mapped onto Basecoat's variables), **jsPDF 2.5.2 + jspdf-autotable 3.8.4** (do NOT bump without retesting — autotable 3.8.x pairs with jsPDF 2.x), **Leaflet 1.9.4** (satellite maps — Esri World Imagery, CORS-enabled so tile canvases are PDF-exportable; satellite-only, opens at `DEFAULT_MAP_VIEW`), **@supabase/supabase-js 2.49.4** (UMD; client named `sb` to avoid clobbering `window.supabase`), **SheetJS xlsx 0.18.5** (Excel import).

- The Leaflet/GPS "not a secure context" caveat does **not** apply on the deployed `https://` site — `navigator.geolocation` works normally there.

## Findings Tracker / Dashboard (`index.html` + Supabase)

The app's landing page and primary daily tool: a register of **abnormal findings** from vendor inspection reports, each tracked through a status lifecycle until repaired — the design goal is "no finding is ever forgotten." Deliberately finding-centric: there is **no pipe-asset register or CML/TML model** (the pipe tag is a plain field on the finding, with autocomplete from previously entered tags plus the master line list below); don't add one without the user asking.

**Location-first identity**: the app serves operators (who know *where* a problem is, not the Line No.) as well as engineers. So **Location Description is the required identity field and Pipe Tag / Line No. is optional** (`pipe_tag` is nullable — an engineer assigns the Line No. later). Everywhere a finding is labeled by its tag — register row, map popup, detail `<h2>`, both PDFs' tag column/header — it **falls back to `location_desc` when `pipe_tag` is empty** (`f.pipe_tag || f.location_desc || '—'`), and the register/summary suppress the separate "Loc:" subline in that case to avoid repeating it. (The findings **bulk import** still requires Pipe Tag — it's an engineer batch path, intentionally not changed.)

- **Backend**: Supabase project `uuwcftjduphtngmhwvrb` (**Singapore** region), URL + `sb_publishable_` key in `shared.js` — safe to commit; every table is RLS-gated to the `authenticated` role.

### Combined finding form + full assessment workbench (`#viewForm`)

A **two-column workbench** (`.form-split`: finding data left, assessment right; stacks below 960px, finding panels first). Left column order: **Finding Info → Anomaly → Position → Photos → Source Inspection → Planning & SAP** (Planning & SAP is last — it's the engineer's later-stage concern). **Inspection Date (`#fInspDate`) lives in the Finding Info identity panel** (not Source Inspection — "when found" is core metadata operators fill early). The identity panel header carries the **"Manage line list"** button (`#btnLineList`, moved off the dashboard toolbar — it's contextual to the Pipe Tag combobox). Planning & SAP holds the **Estimated Repair Cost** field (`#fEstCost` → `estimated_cost`). Right column: the assessment panel (`#assessPanel`, toggled `.on`) — pipe-setup inputs (`a`-prefixed ids: `aNps`/`aSch`/`aMat`/`aTnom`/`aTmeas`/`aDepth`/`aP`/…, default material `API5LB`; **`aCa` sits with the design params, not the reading section**), then the **full live workbench** (`awFormView = paCreateAssessView($('awForm'), …)` — status banner, cross-section with working drag handle, compliance verdicts, ERF gauge, results grid, advisor + equations collapsed, scope notice). One Save records the finding *and* its assessment snapshot.

Behaviors to preserve:
- **Auto-enable** when `fType` ∈ `WALL_LOSS_TYPES` (unless the user toggled manually — `assessToggleTouched`); **Corrosion Type auto-follows the Finding Type** (`CORR_TYPE_BY_FINDING`; CUI/CUS are external).
- `recalcAssessment()` runs the shared `computeB313` live on every input and renders through the workbench. **Neutral-vs-invalid rule**: required-but-empty fields show the grey neutral banner; only actually-invalid typed input shows the red ERROR banner + a targeted message in `#aCalcHint`. (`CA ≥ t_meas` is no longer an error — see the `computeB313` note above — so only `ca < 0` produces a CA message.) The **CA input lives with the design parameters** (next to Design Pressure / Corrosion Type), not in the reading section — it's a design/spec value, not a field measurement; a hint under it says so.
- **Severity auto-suggests** from status (OK→Low/MONITOR→Medium/REPAIR→High) until the user sets it (`severityTouched`).
- `collectForm` derives `t_nominal`/`t_measured` from the assessment section; `collectAssessment` snapshots `{inputs, results}` (results include `erf_no` + `erf_with`; **no-CA is the headline figure everywhere** — current condition at measured thickness; with-CA is the secondary reference) — **deduped on edit** via `lastLoadedAssessInputs`. The snapshot `inputs` shape is the long-standing schema (nps/schedule/material/S/E/W/Y/design_temp/P/p_unit/ca/corr_type/cr/mode/depth/tmeas/override_tnom) — saved rows depend on it.
- **Pipe Tag input is a custom searchable combobox** (`initTagCombo`, not a native `<datalist>`): `#fTag` stays a plain `<input>` (so `collectForm` reads `.value` and `applyTagMemory` fires on `change` unchanged) wrapped in `.combo` with a floating `.combo-menu`. Options come from `buildTagOptions()` — every known tag paired with a **location** (most-recent finding's `location_desc`, or a line-list tag's service) and a **terminal** (from the finding or line-list row, used for scoping — see below) — and typing filters on **tag OR location**, so an operator who knows where the problem is can find the Line No. Free text is always preserved (brand-new tags work); selecting an option sets the value and dispatches `change`. Replaced the old `refreshTagList()`/`#tagList` datalist entirely (the combo reads live `findings`/`lineList` on open). Results are capped at `TAG_COMBO_MAX` (50) with a "Showing N of M — keep typing to narrow" footer row (`.combo-more`) once the match count exceeds it. **`.combo-menu` is `position: fixed`, not `absolute`** — the field lives inside a `.panel`, and `.panel { overflow: hidden }` (theme.css, clips to the card's rounded corners) was clipping an absolutely-positioned menu to just the sliver of card below the input (~2–3 visible rows, a real reported bug). `position: fixed` escapes all ancestor clipping; `initTagCombo` sets `top`/`left`/`width` from `input.getBoundingClientRect()` every time the menu opens (and on resize/scroll while open), since fixed positioning has no anchor of its own. **Scoped to the selected Terminal**: once `#fTerminal` has a value, options are filtered to `!o.terminal || o.terminal === term` — a tag with no terminal on record still shows (can't rule it out), but a KBY selection won't suggest an SRC-only tag. Changing `#fTerminal` while the menu is open live re-filters it (not just on next focus/input).
- **Per-tag memory** (`applyTagMemory`, on tag blur when creating): fills empty P&ID/service/location and restores pipe setup (not the old reading) from the latest finding on that tag — **falling back to the master `line_list` table** when the tag has no prior finding (or no recorded assessment), which fills empty P&ID/service/**terminal** instead (line_list has no location column). A prior finding's own assessment always wins over the line list (field-verified beats bulk-imported reference); metadata fields combine both sources under the same fill-only-if-empty rule rather than one replacing the other (so a location the operator typed first is never clobbered). The `notify()` toast names which source actually supplied the values. **"Save & add another"** keeps terminal/vendor/report-no/inspection-date/method.
- On edit, the latest snapshot restores into the workbench (`loadAssessmentInto`), so "edit the assessment" is just the edit form.

### Detail page (`#viewDetail`)

Two-column layout (`.detail-split`): left Details → Status → **ASME B31.3 Assessment**; right Site Location → Photographic Record → History (kept on the right so the left column doesn't run long). The assessment panel renders the **latest snapshot through a read-only workbench**: `resFromSnapshot(a)` re-runs `computeB313` on the saved `inputs` (single engine source) and mounts `paCreateAssessView` into `#awDetail` (no `onDepthDrag` → handle hidden; advisor/equations collapsed); older snapshots render as compact history rows. A snapshot whose inputs can't re-compute (legacy/malformed) falls back to tiles of its saved `results`, with `erfNo(r)` deriving the no-CA ERF from `mawp_no + P_input` for pre-`erf_no` rows. "Run assessment" routes to `#/edit/<id>`. The detail toolbar is sticky under the app header (`top: var(--app-header-h)`, measured by `syncHeaderHeight()`). The location map (`#detailMap`) needs `invalidateSize()` after un-hiding (0×0 gotcha).

### Quick calculator (`#/calc`, `#viewCalc`)

A standalone what-if workbench — **nothing loads, nothing saves**. Its own small input set (`q`-prefixed ids) + own `paCreateAssessView` instance (`#awQuick`), deliberately **fully independent of the finding form** so a what-if never clobbers a half-entered finding's assessment. Wired in `initQuickCalc()` (same neutral-vs-invalid rule, Reset button restores defaults). Reached from the header's "Quick Calc" button.

### Unified finding PDF (detail toolbar "Export PDF")

`buildFindingPdf()` is **one report for both finding record and assessment**, in the old calculator report's design language. Chrome: `M`=14/`HEADER_H`=18/`FOOTER_H`=16, logo-left/navy-title-right header with 0.8mm navy rule, page-x-of-y + division-attribution footer, navy bold-9 **auto-numbered** `section()` titles (never hardcode a number — optional sections must leave no gap), `{tp}` total pages, `— End of Report —` marker. Fonts: GoogleSans (via `registerGoogleSansFonts`) + courier for numerics.

Content order: colored finding-status band (from `STATUS_COLORS`) → Finding Information → Source Inspection (incl. `doc.textWithLink` Report Link) → Anomaly → Lifecycle & SAP → **assessment block** (only when a snapshot exists *and* re-computes): integrity-status band (PDF_OK/WARN/DANGER) → Assessment Input Parameters autotable → Wall Thickness Cross-Section figure (`paCrossSectionPng`) → Calculation Results autotable with PASS/CHECK verdicts (+ CS-reference caveat + FFS recommendation when checks fail) → Governing Equations with **real stacked fractions** (`drawFractionRow`) → PCC-2 Repair Recommendation (`paAdvisorItems`) → Scope & Limitations (`PA_SCOPE_TEXT`) → Site Location (Figure via `composeMapPng`, resolves null on failure) → Photographic Record (2-up framed, As Found / After Repair) → Status History. A legacy snapshot that can't re-compute falls back to a compact saved-results section. A finding with no assessment simply skips the whole block — same conditional concept as the web UI.

Numbers are **re-derived from saved inputs through `computeB313`** (assessment tables/equations), so PDF and web UI can never disagree. All images (logo/map/photos/cross-section) are pre-awaited before drawing. Semantic colors are the named constants `PDF_OK`/`PDF_WARN`/`PDF_WARN_DARK`/`PDF_WARN_MID`/`PDF_DANGER`/`PDF_NAVY`/`PDF_TEXT`/`PDF_MUTED`/`PDF_BORDER` (matching `:root`'s tokens) — never re-type hex per call site. **Only WinAnsi-safe characters** in PDF strings (no `≥`/`≤` — use `>=`/`<=`; `·`/em-dash/degree are fine). Export uses the `blob:`-anchor native-viewer approach (`openPdfNative` pattern) — never `window.open`+`.location` (opaque-origin failure) or `data:` URLs (Chromium blocks top-level `data:` navigation).

## Running / testing

- Open `index.html` in a browser — no build step. Full function needs a network connection (Supabase + CDNs); verification scripts stub what they need to run on `file://`.
- No automated test suite in the repo; **Playwright verification scripts in the session scratchpad are the established pattern** — verify in-browser rather than assuming correctness from code inspection. Current set (recreate from these descriptions if missing): `verify-form-workbench.js` (two-column form: live recalc parity vs a direct `computeB313` call, severity suggestion, snapshot integrity, drag write-back, neutral/error states, desktop/mobile layout), `verify-detail-workbench.js` (read-only workbench from saved snapshot, legacy fallback, history list), `verify-quick-calc.js` (`#/calc` parity, reset, form independence), `verify-unified-pdf.js` + `render-unified-pdf.js` (build both PDF variants, render every page via pdf.js, assert assessment sections present/absent), `compute-parity.js` (engine numeric-identity guard), and `audit-shots.js` (screenshot matrix: both themes × several widths, console-error capture).

## Conventions to preserve

- Pressure entered in `bar`/`psi`, always converted to **MPa** internally (inside `computeB313`).
- The app has no dark mode — a single light palette only. The app header (`body > header`) is a sticky surface with a thin teal→sky `.header-accent-bar` and the OR logo in a `.hdr-logo-chip`. `syncHeaderHeight()` measures it into `--app-header-h` for anything else sticky.
- Two reading modes (measured thickness vs wall-loss depth) tracked via `.active` on the mode segment buttons; mutually derivable (`t_meas = t_nom − depth`).
- Validation uses `aria-invalid="true"` + `.validation-alert` visibility.
- All numeric display formatting goes through `paFmt(val, decimals)` (`—` for null/non-finite); `fmtN` is the PDF-local equivalent.
- **One font: Google Sans everywhere** (web + PDF). "Google Sans" is proprietary and *not* on the public Google Fonts API, so the web can't `<link>` it — instead `registerGoogleSansWebFont()` (`src/engine/fonts.ts`) injects an `@font-face` from the same embedded base64 TTFs the PDF uses (`PA_GOOGLE_SANS_*`), so the UI genuinely renders in Google Sans, offline-safe, ~zero extra weight. Only Regular(400)+Bold(700) exist, mapped via weight ranges (400–500→Regular, 600–900→Bold). **No JetBrains Mono / no Google Fonts CDN link** anymore — numerics keep `font-variant-numeric: tabular-nums` (Google Sans supports it) so figures still column-align, just not monospace. **Thai text: `'Noto Sans Thai'`** (`@fontsource/noto-sans-thai`, self-hosted npm package, imported in `main.ts` at weights 400/500/600/700) sits right after `'Google Sans'` in the `html, body` stack — Google Sans has no Thai glyphs, and a bare system fallback rendered inconsistently (whichever generic Thai font the OS picked, visually mismatched next to Google Sans). Noto Sans Thai's `@font-face` rules are `unicode-range`-scoped to the Thai block (U+0E01-0E5B), so it only ever supplies the codepoints Google Sans is missing — Latin/numeric text is unaffected. Dense-engineering styling otherwise unchanged: hairline borders, `--radius: 0.5rem`, spacing tuned per component in small (~2–4px) increments (a 2px badge and a 20px card gap are both legitimate, not drift); border-radius scale **6px** interactive controls / **8px** containers, pills use `height/2`.
- Readability floor: 11px for anything actively read; 10px only for short uppercase badge/eyebrow text. `.eq-box` stays `justify-content: flex-start`; the `.fraction`'s internal `text-align: center` is separate and must stay.
- Semantic status colors (`--ok-color`/`--warn-color`/`--danger-color`) and cross-section limit colors (`--limit-reqca`/`--limit-req`/`--limit-struct`) are CSS variables — never hardcode their hex in CSS/SVG attributes. The `--limit-*` values are dark 700–800-tier shades so 11px bold SVG labels clear WCAG AA against `--svg-bg`; the PDF renders via `paSvgToPng`'s injected style block, which duplicates this hex list as static values (CSS vars don't resolve in a standalone serialized SVG) — keep that hex list in sync with theme.css.
- The universal `* { transition: … }` rule in the page is the single source for state-change fades; components only declare their own `transition` for properties it doesn't cover (`transform`, SVG `r`/`stroke`/`fill`/`opacity`, gauge `width`/`left`). When a state class changes a property, check it's in the relevant transition list (`.drag-handle.dragging` changing `stroke` was exactly this bug).
- CSS cascade-order trap: an override placed *earlier* in the stylesheet than the base rule it targets, at equal specificity, silently loses (source order wins) — scope overrides tighter (e.g. `table.list .pill`) instead of relying on media-query placement.
- SVG/XML comments must never contain `--` (breaks `XMLSerializer` for the PDF export path), and JS block comments in the asset files must never contain `*/` mid-text.
